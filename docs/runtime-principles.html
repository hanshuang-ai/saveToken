SaveToken 运行原理

为 Claude Code 的 Bash / Read 文本输出提供保守精简视图，需用时按 handle 取回原文

解决什么问题

Claude Code 执行命令或读文件时，会产生大量文本输出（日志、命令结果、文件内容等）。这些输出全部进入上下文，消耗大量 Token。

核心思路

拦截 Bash / Read 的长文本输出，生成可定位原文的精简视图并落盘备份；需要细节时再用 MCP 工具按 handle 取回。不命中安全门槛的输出原样放行、不留任何痕迹。

10000 字符阈值（低于此不进管道）
6000 通用预览字符上限
100% 采用压缩的原文可完整取回

内容分类的作用

分类不决定"压不压"，只决定"能否走语义摘要"。够长就进管道，不够长或无净收益就放行。

分类 语义摘要资格 未命中摘要时
structured 尝试 structured-digest（仅 Jest 日志套件 / 时间戳日志信号 / 重复快照表） 退回 generic-preview
prose 不摘要 走 generic-preview（首尾 + 采样）
mixed 不摘要 走 generic-preview（首尾 + 采样）

判断依据

  • 扩展名 / 文件名快筛（.log .json .yml .html 等直接判结构化）
  • 二进制检测（含 NUL 或前 2KB 控制字符占比高）
  • 强符号密度（{} ; 占比）
  • 标记标签密度（<tag> 频率）
  • 行结构相似度（排除列表行后的前缀重复度）
  • JSON 合法性
  • 自然语言密度（中文虚词 + 全角标点 + 英文虚词词边界）
  • 是否存在 ANSI 颜色码

安全侧倾斜：有明显自然语言迹象时不会直接判 structured，避免散文被误摘要。

安全保障

策略保守：宁可不压缩也不能丢失信息或暴露不可用 handle。

1
工具白名单

只拦 Bash 与 Read 的字符串文本字段，其他工具输出直接放行

2
大小阈值

小于 10000 字符不进管道，避免对小输出徒增开销

3
严格摘要识别

structured-digest 只认三类机器输出，不泛化；高密度诊断直接跳过不摘要

4
收益验证

必须同时满足：节省 ≥ 512 字符 且 节省比例 ≥ 10%，否则放行

5
先提交后返回

原文、FTS 索引、度量在同一事务提交成功后才暴露精简视图；提交失败则 failed-open，不返回带不可用 handle 的压缩版

6
原文备份 · 放行不留痕

采用压缩的原文 100% 落盘、可按 handle 取回；未达标放行则不存原文、不加任何标记

我们的做法：可还原精简

规则变换 / 截断式延迟加载，省略部分落盘可取回，原文严格可还原

不做的：有损摘要

小模型删"不重要"内容，无法还原，可能丢失关键信息

处理示例

输入 命中的策略 结果
137,199 字符结构化日志 structured-digest 日志信号摘要 2,245 字符（省 98.4%）
约 5 万字符长输出 generic-preview 通用预览 约 6000 字符（预览上限）
省不足 512 字符 / 或不足 10% 未过净收益门槛 原样放行

关于这些数字

大小按 JavaScript string.length（UTF-16 代码单元）统计，不是实测 token 数，也不是账单或端到端成本节省。98.4% 是单条日志用例的实测压缩率，不等于真实工作流平均收益——项目目前不宣称 v2 已在真实场景中建立节省收益。

收益

  • 减少进入上下文的字符量，降低 Token 消耗
  • 省略部分落盘索引，按需取回，不丢信息
  • 自动化处理，无需人工干预
  • 不达门槛即原样放行，对短输出与无收益内容零副作用
